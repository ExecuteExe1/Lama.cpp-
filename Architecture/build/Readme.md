 ## CMakeCache.txt 
  The `CMakeCache.txt` file contains the configuration settings used to build the `llama.cpp` project. It shows that the project was compiled in **Release mode** using GCC/C++ and **CUDA 12.9**, with the CUDA compiler located at `/usr/local/cuda-12.9/bin/nvcc`. Most importantly for GPU profiling, `GGML_CUDA=ON` confirms that the GGML CUDA backend is enabled, while `GGML_CPU=ON` shows that CPU execution is also supported. The configuration also enables CUDA Flash Attention (`GGML_CUDA_FA=ON`) and CUDA Graphs (`GGML_CUDA_GRAPHS=ON`), and links against NVIDIA libraries such as cuBLAS, cuBLASLt, CUDA Runtime, and CUPTI. The cache therefore confirms that the current `llama.cpp` build is configured to use the NVIDIA GPU through the CUDA backend, while retaining CPU support for operations that are not executed on the GPU.

## CMakeFiles dir
The `CMakeFiles` directory inside the `llama.cpp/build` directory contains files and folders generated automatically by CMake during the configuration and compilation of the project. These files are mainly used internally to keep track of build targets, Makefile rules, compiler configuration, testing, code coverage, memory checking, and other build-related operations. For example, directories such as `Continuous`, `Experimental`, and `Nightly` are related to CMake's automated testing infrastructure, while files such as `Makefile2`, `TargetDirectories.txt`, and `CMakeDirectoryInformation.cmake` contain information required to organize and execute the build. These are therefore **not the actual llama.cpp source code or CUDA kernels**; they are build-system files that allow CMake to correctly compile and manage the project. For investigating how llama.cpp uses the GPU, the more relevant directories are `ggml/src/ggml-cuda`, which contains the CUDA implementation and kernel source files.

## CTestTestfile.cmake
The `CTestTestfile.cmake` file is another file automatically generated by CMake to organize the testing structure of the `llama.cpp` project. It records the source and build directories and specifies which subdirectories should also be included when CMake runs the project's tests. In this case, it includes major parts of the project such as `ggml`, `src`, `vendor`, `common`, `tests`, `examples`, `pocs`, `tools`, and `app`. The `tests` directory contains the actual llama.cpp tests, while the other entries allow CMake to process testing information associated with those components. This file is therefore **not part of the llama.cpp implementation itself** and does not contain CUDA kernels or GPU computation; it simply tells CMake and CTest where the different testing-related components of the project are located.
